## 1. What exists today (actual baseline)

Canonical `src/cli.ts` dispatches six commands: `init` (may write configuration; not a read-only verifier), `doctor` (diagnostic), `check` (real existing assurance with receipt v1.0), `review` (no LLM reviewer executed), `test` (renders a plan, no test engine executed), and `security` (NOT_RUN-only report, no scanner invoked). **Review, including empty scope, currently may emit NOT_RUN with exit 0. `test --profile standard` currently emits a plan/exit 0. `security` currently emits NOT_RUN/exit 1**. These are truthful source observations about current limitations, **not** desired V2 success states.

Existing `check` exit precedence: `2 ERROR > 3 TREE_DRIFT > 1 FINDING/FAIL/FLAKY > 4 INCOMPLETE > 0 COMPLETE-CLEAN`, computed by `src/receipt/model.ts`. `completeness` stays independently visible even when code 1 wins. Keep receipt v1.0 byte-identical. Proposed A07 introduces claim `REFUTED` only with separately qualified contradiction, not on a raw untrusted scanner finding; extending `review/test/security` exits to 0/1/2/3/4 is a **breaking compatibility change**, including `security` 1→4 on missing work. **FD-1 is required before this code change**.

**Trust:** No default hosted model, SaaS, telemetry, data export, registry publication, agent-initiated permission escalation or untrusted subprocess. A process-tree killer/Windows Job Object is T0 lifetime control, **not** full filesystem+network isolation. Host-only human override is per invocation and never grants T1. All extensions stay T0/BLOCKED for untrusted code until real native hostile probes qualify that OS.
