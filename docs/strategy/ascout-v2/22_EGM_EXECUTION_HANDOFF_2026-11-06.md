## 1. Product contract and non-negotiable boundaries

**Goal:** A local-first, free-to-operate, evidence-bound verification tool for AI-generated software where a real engine runs and the result can be tied to exact source bytes. Users must know **what ran, what failed, what was blocked, what was skipped, and what was never checked**. A receipt may never use absence, stale evidence, host-agent assertions, or a model's suggestion as a substitute for independent execution.

**Preserve:** Ascout's existing TypeScript trust kernel, `ascout check` and receipt v1.0 semantics, source-start SHA plus end-of-run drift check, bounded execution/redaction, the qualified existing Playwright path, existing findings/coverage/omission policies, and source history. No required account, hosted service, paid inference, default telemetry, arbitrary dynamic plugin, cloud browser, or remote repository upload.

**Architectural recommendation (requires founder ratification):** one TypeScript claim authority; one bounded execution broker for all new child processes; versioned out-of-process engine envelopes; explicit signed/hashed binary and endpoint identity; federated *observations* from qualified scanners but a **single Ascout claim authority**; optional Sentrdel native analysis; OCR review with local or explicitly user-funded provider or a lower-independence host delegation; optional deterministic TesterArmy only after the existing Playwright path remains authoritative for its own observations. Copy/port only rights-cleared pinned source. Keep required Apache-2.0/BSD/MIT attribution, provenance and nested third-party notices.

**Trust invariant:** an agent, MCP tool, scanner, model, test runner, or imported skill cannot self-authorize an effect or publish a success claim. Untrusted project code stays blocked without a proved containment tier, not merely a Job Object or process timeout. A human trusted-local override is invocation-only, never silently added by agents, and cannot assert containment.

## 4. Data, error, privacy and verification contracts

1. **Immutable bind:** every engine request/response includes engine version/hash, source-start full HEAD, tree digest, configuration/policy digest, selected targets, run ID and invocation identity. Old-head fixtures and cached model outputs are never current evidence.
2. **Failure lattice:** `NOT_RUN` (never executed), `BLOCKED` (policy/permissions), `ERROR` (runtime/malformed), `FAIL` (actual negative finding), `FLAKY` (conflicting reruns), `INCOMPLETE` (required coverage absent), `REFUTED` (only qualified independent contradiction). The CLI exit taxonomy is proposed in [09](09_ASSURANCE_EVIDENCE_CONTRACTS.md); fail closed. A plan preview can succeed as a *plan operation* but must not render an assurance PASS.
3. **Privacy:** no default uploads, account, telemetry, external API, log disclosure, source exfiltration, hosted model, paid service, or unrestricted agent authority. Invoke local binary with scrubbed environment and bounded outputs, redact raw secret-shaped findings, and explicitly admit any endpoint/egress.
4. **Evidence grade:** L0 mocks = contract only; L1 real captured donor output = parser only; **L2 actual binary invoked through Ascout** on one claimed OS; **L3 independently qualified live execution on every OS claimed**. A green unit-test matrix does not promote L0 to L2 or L3.
5. **Negative tests:** a no-op success, missing binary, forged manifest, stale HEAD, poisoned report/cache, repository-controlled Git executable, skipped subtest, secret in scanner output, unapproved egress, untrusted test script, and impossible T1 on macOS/Windows must each be visibly refused/failed with no false green.
6. **Runbook:** for each patch: `npm ci --ignore-scripts --no-audit --no-fund`, `npm run typecheck`, focused `npx --no-install vitest run <exact test files>`, `npm test` where resource budgets allow, `npm run build`, `git diff --check`, OS-native verification, remote exact-head CI, independent review, and post-merge checks. Record every NOT_RUN/FAIL rather than recycling earlier passes.
